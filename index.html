📌 Supuestos y Alcance del Prototipo

  • Aplicación 100% en el cliente (HTML/CSS/JS) con persistencia en localStorage del navegador; no hay backend real, base de datos ni servidor TLS — la seguridad de transporte/reposo se documenta como objetivo de producción.
  • El "último día hábil del ciclo" se simplifica: la generación automática se dispara cuando la fecha del sistema alcanza o supera la próxima fecha de generación (sin calendario de festivos).
  • El "cobro" (pago recibido) es un registro manual simplificado dentro de Estado de Cuenta / Libro Auxiliar, ya que el manual no describe un módulo de tesorería.
  • El MFA se simula mostrando el código en pantalla (sin envío real de correo/SMS) y el SSO se deja como punto de integración documentado.
  • Los cálculos de retención usan tasas de ejemplo configurables; deben ajustarse a la normativa DIAN vigente antes de un uso real.
